## [Unreleased]

### 新增

**M2.9 — 测评反馈（schema v7）**

- **处理法可多选**：`coffee_beans.process` 改成 JSON 数组（如「水洗 + 厌氧」），
  表单是 FilterChip 多选；老数据在迁移里自动包成单元素数组
- **磨豆机加「每 click 位移」**：`grinders.micronsPerClick`，把「调粗/调细几格」
  换算成刀盘间隙变化，方便跨磨豆机对比；豆库的磨豆机卡片也会显示
- **磨豆机卡片第一栏改成「名称 / 零点」**：当前刻度不再混进标题，
  每圈 click / 每 click µm / 最近使用日期放在第二行
- **老研磨度关联老记录**：记录写入时把**当时的零点与每圈 click** 快照下来
  （`brew_logs.grinderZeroPointSnapshot` / `grinderClicksPerRevolutionSnapshot`）——
  之后换刻度或重新校准零点，历史记录仍按当时的零点解释，不会被重新换算
- **删除记录自动回补余量**：按各支豆子当时的粉量原路退回（事务内完成）。
  **这条改掉了手册 §6.2 原来的「删除不回补」规则**，手册已同步
- **「新增一杯」从归零页开始**：点 dock 加号开的是空表单，不再预填上次的参数；
  想复用就点右上角复制按钮（长按还能从收藏里挑）
- **自定义方法归到「其他」**：记录时 `method = other` + `methodLabel = 原文`
  （原来落在「手冲」上，按方法统计/筛选会串味）；chip 配色与内置项**完全一致**
- **辅料单位框对齐**：单位下拉用 `InputDecorator` 包起来，边框与高度和名字/数量框一致
- **研磨刻度改成「圈 + click」**：知道「每圈几 click」的磨豆机，第一个框就是**圈数**，
  提示行自动算出**绝对刻度**（`零点 + 圈 × 每圈 click + click`），不用自己心算；
  零点取记录里的**快照**，所以后来改零点不会把老记录的读数重新解释。
  没有这个字段的电动磨退回原来的「研磨刻度」相对展示

### 修复

- **豆库「总余量」实时更新**：原来 `batchesByBeanProvider` 是 FutureProvider 且只依赖
  豆子列表 —— 冲一杯扣余量、加一袋复购都只动批次表，列表上的总余量会停在旧值。
  改成订阅批次表的 StreamProvider
- **`IntField` 输入不刷新提示行**：它只有 `controller`、没有 `onChanged`，
  在 click 框里打字不会 `setState`，于是「绝对刻度」停在改之前的值
  （填 1.5 圈时还显示 0 click）。补上可选 `onChanged` 并在研磨行接线

### 变更

**M2.9 — 测评反馈（schema v7）**

- **`schemaVersion` 7**：`coffee_beans.process` 从单值文本改写为 JSON 数组，
  新增 `grinders.micronsPerClick`、`brew_logs.grinderZeroPointSnapshot`、
  `brew_logs.grinderClicksPerRevolutionSnapshot`。四步都是加列 / 改写值，
  **没有重建表**（重建会触发外键级联，把子表数据带走）
- 测试 285 → **292** 个用例

**M2.8 — 第二批：自定义冲煮方法 / 辅料（schema v6）**

- **自定义冲煮方法**：方法不再限于内置六个，可以自己加「拿铁」「摩卡」「燕麦拿铁」。
  方法 chip 行 = 内置主力 + 自定义（浅色区分）+ `＋`（弹输入框新建）+ `更多方法`；
  **长按自定义 chip** 可重命名 / 从列表删除（只改列表，历史记录保留原来的写法）
- **辅料**：表单新增「辅料」一栏，记牛奶、榛果糖浆这类额外加的东西与用量
  （单位 `ml / g / 泵 / 份`，数量可留空表示「只记加了什么」）。
  名字从面板里选：**常用**（内置 8 项）+ **最近用过**（从本机记录自动聚合）+ **新建**。
  记录卡片上有辅料时多一行，最多两项、其余折叠成 `+N`
- **语义（用户定的）**：**方法记做法、辅料记加了什么** —— 「拿铁」既可以当方法，
  也可以拆成「方法 = 意式浓缩 + 辅料 = 牛奶 150ml」，两条路都支持

**M2.8 — 第一批：记录交互（纯前端）**

- **日期/时间弹窗中文化**：加 `flutter_localizations` 并把界面语言锁在 `zh_CN`。
  此前 `showDatePicker` 的月份、星期、按钮全是英文的「September / OK / Cancel」
- **冲煮时间可选到时分**：新增 `DateTimeField`（日期与时分**两个按钮**，点哪个改哪个）。
  新建记录时选完日期、如果从没设过时分，会顺手弹一次时间选择；
  编辑旧记录不弹（它的时分是当时真实的时间）。时间按钮只有分钟精度，秒会清零
- **记录卡片第一行改为「所有豆名 + 方法 chip + 评分星」**：
  方法 chip 从第二行挪到第一行、紧跟豆名（豆名过长则省略，chip 始终完整）；
  第二行只剩下研磨刻度。拼配记录显示成 `黑猫拼配 + 花魁 [拿铁]`
- **收藏 / 删除改为左滑**：`SwipeActions` 镜像成左滑（手指从右往左），
  按钮出现在右侧 —— 收藏在前、删除在最外侧
- **应用图标换成用户提供的成品图**：米白圆角方块 + 深棕圆环 + 咖啡豆 + 一圈刻度点。
  原图留档 `assets/icon/app_icon_source.png`，生成脚本 `tool/make_app_icons.ps1`
  按亮度抠背景，输出传统图标（48–192）与自适应前景（×2.25）；
  自适应背景色改为原图米白 `#F3EBDC`
- 渲染稿与渲染脚手架：`tool/design_preview/`（真主题 + 真中文字体 + 真图标字体），
  见 `docs/M2.8-UI设计稿.md`

### 修复

**M2.7 — 记录交互（schema v5）**

- **底部 dock 改两栏 + 中间固定的圆形加号**：原来那颗悬浮的大 `+`（`FloatingActionButton.large`）
  会和列表最后一条打架、滚动时还会挡内容，现在并进 dock 正中，
  位置永远不变、列表也不用再留一大截空白
- **新增入口统一圆圈加号**：豆库右下角（咖啡豆 / 磨豆机）、豆子编辑页的「再来一袋」、
  冲煮表单里内联的「新增豆子 / 新增磨豆机」全部改用 `Icons.add_circle_outline`
  （图标常量集中在 `lib/core/icons.dart`，避免以后又长出第二种样式）
- **记录右滑操作**：每条记录向右滑动露出「收藏」与「删除」；（M2.8 已改成**左滑**，见上）
  收藏只改标记（不碰余量、不影响「最佳参数」），删除要二次确认且**不回补余量**
- **「收藏」入口**：记录页搜索框下方加了「全部 / 收藏」筛选，
  收藏过的记录卡片上会显示书签图标
- **复制按钮分单击与长按**：单击复制**上次**参数（原行为）；
  长按弹出面板，从**收藏过的参数**里挑一条复制（每条显示豆子 / 方法 / 刻度 / 粉水 / 评分 / 日期）；
  一条收藏都没有时，面板会说明「左滑记录即可收藏」
- **表单里也能收藏**：「评价」区新增「收藏这套参数」开关，与记录页滑动等效

**M2.6 — 批次模型 / 多豆 / 扩展属性（schema v4）**

- **批次模型**：新增 `bean_batches` 表，烘焙日期、烘焙度、余量、购入总重、价格
  从豆子下移到批次。**复购**变成「给同一支豆子加一袋」，而不是再建一支重名的豆子。
  余量扣减改为按批次，批次挑选用「烘焙日期 → 创建时间 → id」排序链
- **多豆冲煮**：新增 `brew_log_beans` 表，一条记录可关联多支豆子（拼配），
  各自粉量与批次；编辑时按各支豆子的粉量差值补扣、去掉一支则回补
- **拼配录入界面**：豆子一栏可以「加一支（拼配）」，每支填占比，
  「粉量」变成总粉量并按其分摊（零头归最后一支，保证各支之和 == 总粉量）；
  占比合计不是 100% 会拦住保存；同一支豆子不能重复选；去掉一支时总粉量
  同步减掉那一支，剩下几支的实际克数不变。记录卡片显示 `A + B` 与各自克数
- **删除豆子保留历史**：用量行换自增主键 + 豆名/烘焙日期快照，
  删豆子时 `beanId` 置空但用量行保留，拼配记录不再丢历史
- **扩展属性**：新增 `extra_attributes` 表与通用编辑器，覆盖豆子 / 磨豆机 /
  冲煮记录 / 批次 / 配方五类对象。**只记录、只展示**的属性加一行定义即可，
  不动表结构、不写迁移；需要筛选/排序/统计的属性仍应晋升为一等列
  （判断标准与完整步骤见 `docs/添加新属性指南.md`）
- **枚举前向兼容**：枚举列改用裸 `text()` + 容忍转换器，认不出的值回退而不是抛异常
  （Drift 的 `textEnum` 会让「新版本加了冲煮方法，旧版本读到就崩」）
- **索引**：补 4 个索引（外键与时间线），此前全是全表扫描
- **导出**：JSON 升到 `schemaVersion 2`，新增 `beanBatches` 段；
  CSV 新增「咖啡豆批次」表，拼配记录的豆子列输出 `A 70% + B 30%`
- **数据库迁移改成逐列搬迁**：`onUpgrade` 从「删表重建」换成 `_upgradeToV4`——
  建新表 → 把烘焙日期/烘焙度/余量/购入总重/价格搬成每支豆子的第一个批次 →
  用 `brew_logs.beanId` 回填用量行与烘焙快照 → 最后才删掉 `coffee_beans` 上搬走的列。
  **v1 用户的豆子、记录、设置项全部保留**，不再丢数据
- **迁移加了工具锁**：`test/drift/schemas/drift_schema_v4.json` 是 v4 的冻结快照，
  `test/data/schema_snapshot_test.dart` 两个守门用例——
  ① 当前代码的表结构必须与快照逐列一致（改了表忘了重新 dump 就红，
  失败信息直接点名那一列）；② 拿 v4 快照灌真实数据、用当前代码打开（真跑
  `onUpgrade`）后断言数据一条不少。`oldVersion` 永远钉在 4，
  以后每次升 `schemaVersion` 自动变成「v4 → 新版本」的保活测试。
  于是**M2.6 及以后的数据，任何升级都不会被静默清掉**
- **豆库界面**：卡片展示批次聚合（总余量、批次数、最近烘焙距今天数、收藏）；
  新增批次编辑页，「再来一袋」与编辑批次共用

## [0.1.0] - 待发布

### 新增

**M0 — 立项**

- 项目立项，开发手册 v0.2 定稿（第 17 节 8 项待确认全部关闭）

**M1 — 数据模型与应用外壳**

- 数据层：Drift schema v1，5 张表（`coffee_beans` / `grinders` / `brew_logs` / `recipes` / `app_settings`），
  外键 `ON DELETE SET NULL`，建库时种入 7 项默认设置
- 仓储层：豆库、磨豆机、冲煮记录、设置四个 Repository
  - 余量自动扣减规则落地（新建按粉量扣、编辑按差值补扣、删除不回补、下限 0）
  - 调磨对比查询（同豆同磨按刻度升序）、最近一杯（复制上次的数据来源）
- 领域层：5 个实体 + 4 个枚举，全部支持 JSON 往返（导出功能基础）
- 状态层：Riverpod providers（数据库、仓储、主题、列表、设置）
- UI：咖啡棕主题（浅色米白 / 深色深棕黑）、4 tab 外壳 + 中间 FAB、
  记录 / 豆库 / 统计 / 我的四页骨架与空状态
- 设置项真读写数据库：主题模式（浅色/深色/跟随系统）、冲煮后自动扣减余量

**M2 — P0 表单**

- **咖啡豆表单**：新增 / 编辑 / 删除；名称必填校验；产地、庄园、处理法、
  烘焙度、烘焙日期、风味标签、余量与购入总重（含消耗比例实时提示）、价格、备注
- **磨豆机表单**：新增 / 编辑 / 删除；品牌与型号必填；刀盘类型（含常用快捷项）、
  刻度单位、零点、每圈 click；底部实时预览 `C40 / 22 click / 零点 0` 展示格式
- **冲煮记录表单**：新增 / 编辑 / 删除
  - 方法选择（手冲 / 摩卡壶 + 可展开的更多方法）
  - 豆子与磨豆机下拉，可在表单内**就地新增**并自动选中
  - 研磨刻度与 click；粉量 / 水量填写后**自动算出粉水比**
  - 水温、总时间（实时显示 `m:ss`）、滤杯、冲煮时间可改
  - 评分（1–5 星，可点掉取消）、风味标签、备注、「标记为最佳参数」
- **复制上次**（手册 §8）：记录页 FAB 带着上次参数直接进表单；
  刻意**不继承评分、备注与最佳标记**，且不继承记录 id（生成新记录而非覆盖）
- **摩卡壶专属字段**：火力、出液量、上壶预热（选摩卡壶时才出现）
- **专业字段折叠**：TDS、萃取率、水质 ppm、环境温湿度、豆温、压力
- **余量联动提示**：保存时按设置自动扣减；余量不足则扣至 0 并弹出「余量不足」提示
- **删除一致性**：删除豆子 / 磨豆机后历史记录保留、外键置空；
  删除记录不回补余量（手册 §6.2）
- 表单字段加了稳定的 `Key`（如 `brew.dose`），便于测试与后续自动化

**M2.5 — P0 导出（收口）**

- **JSON 完整备份**：4 张表（咖啡豆 / 磨豆机 / 冲煮记录 / 配方）全字段导出，
  带 `schemaVersion`、`appVersion`、导出时间与各表计数；缩进 2 空格，人也能读
- **CSV 表格**：4 张表分段拼在同一文件，中文表头；**带 UTF-8 BOM**，
  Excel / WPS 打开中文不乱码
- **导出时二选一**（手册 §17 决策 8）：设置 → 导出数据 → 弹窗选择，
  **JSON 为默认**；选择会写入设置表，下次默认选中上次用过的格式
- **导出后分享**：文件写入应用文档目录（不是临时目录，取消分享后仍可找回），
  再唤起系统分享面板让用户保存或发送；分享失败不影响文件已写成功的事实
- **CSV 注入防护**：以 `= + - @` 开头的用户输入会加单引号前缀，
  避免表格软件把它当公式执行
- **备份可读回**：`decodeJson` 能把备份解析回实体，为下一步「导入」预留落点，
  并有往返一致性测试守住
- `ExportService` 抽出 `Exporter` 接口，UI 只依赖接口，便于测试注入
