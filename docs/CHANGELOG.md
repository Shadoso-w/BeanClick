## [Unreleased]

### 新增

**M2.6 — 批次模型 / 多豆 / 扩展属性（schema v4）**

- **批次模型**：新增 `bean_batches` 表，烘焙日期、烘焙度、余量、购入总重、价格
  从豆子下移到批次。**复购**变成「给同一支豆子加一袋」，而不是再建一支重名的豆子。
  余量扣减改为按批次，批次挑选用「烘焙日期 → 创建时间 → id」排序链
- **多豆冲煮**：新增 `brew_log_beans` 表，一条记录可关联多支豆子（拼配），
  各自粉量与批次；编辑时按各支豆子的粉量差值补扣、去掉一支则回补
- **拼配录入界面**：豆子一栏可以「加一支（拼配）」，每支填占比，
  「粉量」变成总粉量并按其分摊（零头归最后一支，保证各支之和 == 总粉量）；
  占比合计不是 100% 会拦住保存；同一支豆子不能重复选；去掉一支时总粉量
  同步减掉那一支，剩下几支的实际克数不变。记录卡片显示 `A + B` 与各自克数
- **删除豆子保留历史**：用量行换自增主键 + 豆名/烘焙日期快照，
  删豆子时 `beanId` 置空但用量行保留，拼配记录不再丢历史
- **扩展属性**：新增 `extra_attributes` 表与通用编辑器，覆盖豆子 / 磨豆机 /
  冲煮记录 / 批次 / 配方五类对象。**只记录、只展示**的属性加一行定义即可，
  不动表结构、不写迁移；需要筛选/排序/统计的属性仍应晋升为一等列
  （判断标准与完整步骤见 `docs/添加新属性指南.md`）
- **枚举前向兼容**：枚举列改用裸 `text()` + 容忍转换器，认不出的值回退而不是抛异常
  （Drift 的 `textEnum` 会让「新版本加了冲煮方法，旧版本读到就崩」）
- **索引**：补 4 个索引（外键与时间线），此前全是全表扫描
- **导出**：JSON 升到 `schemaVersion 2`，新增 `beanBatches` 段；
  CSV 新增「咖啡豆批次」表，拼配记录的豆子列输出 `A 70% + B 30%`
- **数据库迁移改成逐列搬迁**：`onUpgrade` 从「删表重建」换成 `_upgradeToV4`——
  建新表 → 把烘焙日期/烘焙度/余量/购入总重/价格搬成每支豆子的第一个批次 →
  用 `brew_logs.beanId` 回填用量行与烘焙快照 → 最后才删掉 `coffee_beans` 上搬走的列。
  **v1 用户的豆子、记录、设置项全部保留**，不再丢数据
- **迁移加了工具锁**：`test/drift/schemas/drift_schema_v4.json` 是 v4 的冻结快照，
  `test/data/schema_snapshot_test.dart` 两个守门用例——
  ① 当前代码的表结构必须与快照逐列一致（改了表忘了重新 dump 就红，
  失败信息直接点名那一列）；② 拿 v4 快照灌真实数据、用当前代码打开（真跑
  `onUpgrade`）后断言数据一条不少。`oldVersion` 永远钉在 4，
  以后每次升 `schemaVersion` 自动变成「v4 → 新版本」的保活测试。
  于是**M2.6 及以后的数据，任何升级都不会被静默清掉**
- **豆库界面**：卡片展示批次聚合（总余量、批次数、最近烘焙距今天数、收藏）；
  新增批次编辑页，「再来一袋」与编辑批次共用

### 修复

- **冲煮记录表单不扣余量**：表单只写 `brew_logs.doseGrams`，没有同步
  `brew_log_beans` 的用量行，导致从界面保存/编辑记录时**批次余量一分没动**。
  现在 `_save` 会用 `_usagesFromPicks()` 把豆子选择与粉量对齐成用量行

### 变更

- **测试全量迁移到批次模型**：`test/` 下 242 个用例全部通过；
  `test/data/schema_v3_test.dart` 改名为 `test/data/design_decisions_test.dart`
  （表结构已到 v4，旧名字与内容不符）
- 测试脚手架新增 `addBeanWithBatch` / `addBrewLog` 组合夹具，以及
  `fillField` / `readField` / `tapKey` / `tapSaveButton` 等表单操作扩展

## [0.1.0] - 待发布

### 新增

**M0 — 立项**

- 项目立项，开发手册 v0.2 定稿（第 17 节 8 项待确认全部关闭）

**M1 — 数据模型与应用外壳**

- 数据层：Drift schema v1，5 张表（`coffee_beans` / `grinders` / `brew_logs` / `recipes` / `app_settings`），
  外键 `ON DELETE SET NULL`，建库时种入 7 项默认设置
- 仓储层：豆库、磨豆机、冲煮记录、设置四个 Repository
  - 余量自动扣减规则落地（新建按粉量扣、编辑按差值补扣、删除不回补、下限 0）
  - 调磨对比查询（同豆同磨按刻度升序）、最近一杯（复制上次的数据来源）
- 领域层：5 个实体 + 4 个枚举，全部支持 JSON 往返（导出功能基础）
- 状态层：Riverpod providers（数据库、仓储、主题、列表、设置）
- UI：咖啡棕主题（浅色米白 / 深色深棕黑）、4 tab 外壳 + 中间 FAB、
  记录 / 豆库 / 统计 / 我的四页骨架与空状态
- 设置项真读写数据库：主题模式（浅色/深色/跟随系统）、冲煮后自动扣减余量

**M2 — P0 表单**

- **咖啡豆表单**：新增 / 编辑 / 删除；名称必填校验；产地、庄园、处理法、
  烘焙度、烘焙日期、风味标签、余量与购入总重（含消耗比例实时提示）、价格、备注
- **磨豆机表单**：新增 / 编辑 / 删除；品牌与型号必填；刀盘类型（含常用快捷项）、
  刻度单位、零点、每圈 click；底部实时预览 `C40 / 22 click / 零点 0` 展示格式
- **冲煮记录表单**：新增 / 编辑 / 删除
  - 方法选择（手冲 / 摩卡壶 + 可展开的更多方法）
  - 豆子与磨豆机下拉，可在表单内**就地新增**并自动选中
  - 研磨刻度与 click；粉量 / 水量填写后**自动算出粉水比**
  - 水温、总时间（实时显示 `m:ss`）、滤杯、冲煮时间可改
  - 评分（1–5 星，可点掉取消）、风味标签、备注、「标记为最佳参数」
- **复制上次**（手册 §8）：记录页 FAB 带着上次参数直接进表单；
  刻意**不继承评分、备注与最佳标记**，且不继承记录 id（生成新记录而非覆盖）
- **摩卡壶专属字段**：火力、出液量、上壶预热（选摩卡壶时才出现）
- **专业字段折叠**：TDS、萃取率、水质 ppm、环境温湿度、豆温、压力
- **余量联动提示**：保存时按设置自动扣减；余量不足则扣至 0 并弹出「余量不足」提示
- **删除一致性**：删除豆子 / 磨豆机后历史记录保留、外键置空；
  删除记录不回补余量（手册 §6.2）
- 表单字段加了稳定的 `Key`（如 `brew.dose`），便于测试与后续自动化

**M2.5 — P0 导出（收口）**

- **JSON 完整备份**：4 张表（咖啡豆 / 磨豆机 / 冲煮记录 / 配方）全字段导出，
  带 `schemaVersion`、`appVersion`、导出时间与各表计数；缩进 2 空格，人也能读
- **CSV 表格**：4 张表分段拼在同一文件，中文表头；**带 UTF-8 BOM**，
  Excel / WPS 打开中文不乱码
- **导出时二选一**（手册 §17 决策 8）：设置 → 导出数据 → 弹窗选择，
  **JSON 为默认**；选择会写入设置表，下次默认选中上次用过的格式
- **导出后分享**：文件写入应用文档目录（不是临时目录，取消分享后仍可找回），
  再唤起系统分享面板让用户保存或发送；分享失败不影响文件已写成功的事实
- **CSV 注入防护**：以 `= + - @` 开头的用户输入会加单引号前缀，
  避免表格软件把它当公式执行
- **备份可读回**：`decodeJson` 能把备份解析回实体，为下一步「导入」预留落点，
  并有往返一致性测试守住
- `ExportService` 抽出 `Exporter` 接口，UI 只依赖接口，便于测试注入
