# 推送前信息审核（REVIEW-BEFORE-PUSH）

> 适用范围：任何一次 `git push` / 建 PR / 发 Release 之前。
> 适用仓库：`BeanClick`（**公开**仓库，`main` 已发过两个 tag）。
>
> **前提**：一旦推上去就是永久公开。审核标准按"最坏情况公开"来定，不按
> "反正现在没人看"来定。已经推上去的内容改不回来（见 §8）。

本文档本身要入库，所以**描述本机特征一律用占位符**，不得写入真实值。
占位符约定见 §9。

---

## 1. 角色与流程

| 角色 | 谁 | 能做什么 |
|---|---|---|
| 发起者 / 决定者 | Lead | 发起审核、决定改不改、执行 `git add/commit/push` |
| 审核员 | info-reviewer | **只读**检查、出意见、复核。不碰 git，不改产品代码 |

流程（五步，缺一步不算审完）：

1. **Lead 发范围** —— 分支名 / `git diff --stat` / "我要提交这些文件"。
   范围必须具体到文件；只说"改了点东西"无法审。
2. **审核员检查** —— 跑 `tool/check_upload_safety.ps1`（§6），
   再加上脚本查不到的人工项（§7，主要是看图片）。
3. **审核员出报告** —— 三选一结论 + 逐文件表格 + 每条的具体改法（§5 模板）。
4. **Lead 决定并执行** —— 采纳 / 部分采纳 / 记录风险后照推。
   审核员**不代替** Lead 执行任何 git 操作。
5. **复核** —— 改动落地后，审核员重跑脚本，确认 `BLOCK=0` 且 WARN 已逐条有结论；
   **复核通过前不推**。

**范围一变就作废**：如果第 4 步之后又加了新文件或改了内容，回到第 1 步重审。
"就多传一张图"是这类事故最常见的入口。

## 2. 严重度分级与判定口径

| 级别 | 含义 | 典型触发 | 处理 |
|---|---|---|---|
| **阻断 BLOCK** | 一旦公开即造成不可逆损失 | 私钥 / 密钥库 / `key.properties` / 真实口令 / token；个人目录路径（`<盘符>:\Users\<本机用户名>`）；`build/`、`dist/`、`.dart_tool/` 被 track | **修完再推**，没有例外 |
| **警告 WARN** | 不该公开或需要说明 | 其它因机器而异的绝对路径（尤其是**代码/脚本**里的）、设备型号/序列号、内网 IP 与本机端口、私人邮箱、可一条命令重生成的预览产物、>512KB 的二进制、真实个人数据 | **逐条给结论**：改掉 / 明确记录"为什么可以留" |
| **提示 INFO** | 有意约定或观察项 | 文档里写明的工具链路径（项目约定）、生成源码 `*.g.dart`、golden 基线、文件必要性可优化 | 知悉即可，不必逐条处理 |

判定口径要点：

- **凭据类一律阻断**，哪怕"看起来是占位符"——先当真实值查证，再降级。
- **个人目录路径按阻断处理**：`<盘符>:\Users\<本机用户名>` 与
  `<盘符>:/home/<本机用户名>` 直接等于身份泄露，且极易被自动化收集。
- **机器路径要看它在哪个文件里**：
  - 在 `docs/*.md` 里，且是**有意写明的项目约定** → 提示（但仍建议泛化，见 §4C）；
  - 在 `lib/`、`test/`、`tool/*.ps1`、`tool/**/*.dart` 里 → **警告**，
    因为这是"本机环境写死进代码"，换台机器就跑不通。
- **WARN 不是"可以忽略"**，是"需要一个人做决定"。没有任何结论的 WARN 视为未审核。

## 3. 审核三类

### A. 必要性 —— 避免过度上传

判据一句话：**别人要开发 / 构建 / 理解这个项目，是否必需这个文件？**

| 结论 | 对象 |
|---|---|
| 必需，保留 | 源码、测试、构建配置、schema 快照、项目文档、可复现的工具脚本、许可与模板 |
| 默认排除 | 能一条命令重生成的产物：`build/`、`dist/`、`*.apk`、缓存、`<工程根目录>/sqlite3.dll`、`tool/out/*.png` 这类预览图、一次性诊断脚本（`_diag*.ps1`）、草稿 |
| 例外，可保留 | 承担**设计决策留档**职责的图（定稿图是讨论结果的证据）。**必须写出理由**，并回答下面这个问题 |

**例外的判定问题**：*能不能在别人的机器上一条命令重新生成？*

- 能 → 只留脚本，图不入库。
- 不能（例如渲染依赖本机字体 `<盘符>:\Windows\Fonts\<字体文件>`、依赖本机 Flutter
  缓存里的图标字体）→ **图本身就是唯一证据**，保留合理，但要在文档里写明
  "为什么本地才能重生成"。

同时必查：有没有误入的**大文件 / 二进制 / 密钥库 / 数据库文件**。
按当前口径，单个二进制 > 512KB 就要在报告里出现一次。

### B. 本机信息泄露

按线索去搜，**是线索不是结论**，要自己扩展模式：

> 下面几行是"要搜什么"的清单，本身会写出敏感模式的样子。这类行用
> `upload-safety:ignore` 标记，让扫描脚本跳过它们——这是该标记的正当用法。
> **不要**用它掩盖真实值。

| 子类 | 线索 | 级别 |
|---|---|---|
| B1 凭据 | `key.properties`、`*.p12` / `*.jks` / `*.keystore` / `*.pepk`、`-----BEGIN <类型> PRIVATE KEY-----`、`storePassword=` / `keyPassword=` 后跟真实值、`ghp_…` / `github_pat_…` / `AKIA…`、`.env` | 阻断 |
| B2 绝对路径与本机布局 | `<盘符>:\…`、`<盘符>:/…`、`<盘符>:\Users\<本机用户名>`、`$PSHOME`、SDK / JDK / Flutter / Gradle 的本地安装路径 | 个人目录=阻断；其余=警告（文档约定可降级为提示） upload-safety:ignore |
| B3 设备标识 | adb 序列号、真实手机型号（含厂商内部型号串）、Android 版本、厂商系统版本、设备名 | 警告 |
| B4 图片里的人身/位置信息 | 手机桌面壁纸、天气与定位城市、步数、桌面第三方 App 列表、通知内容 | **只能人眼看图**，见 §7 |
| B5 网络与本机服务 | 本机代理（`127.0.0.1:<本机端口>`）、内网 IP（`192.168.…` / `10.…`）、私有主机名 | 警告 |
| B6 身份 | 私人邮箱、真实姓名、账号口令提示 | 私人邮箱=警告；配合凭据出现=阻断 |
| B7 真实个人数据 | 真实咖啡豆名 / 磨豆机名 / 冲煮记录、导出的 JSON/CSV、数据库文件 | 警告 |

**B7 的关键区分**：

- 测试夹具里用**真实品牌名**（常见豆子产地、常见磨豆机型号）→ 可接受。
- **真实个人记录**（本人实际买过的豆子、实际冲煮历史、实际余量/价格）→ 不可接受。

> 注意：GitHub 账号名本身在公开仓库里是公开信息，**不算泄露**；
> 私人邮箱算。

### C. 硬编码

每一处硬编码给**三档之一**：

| 档 | 含义 | 例子 |
|---|---|---|
| **合理** | 有明确理由、稳定、读代码一眼看懂 | 主题色、布局尺寸、语言锁 `Locale('zh','CN')`、协议常量 |
| **建议提取** | 应该变成命名常量 / 配置项 / 派生值 | 魔法数字、重复出现的阈值与颜色字面量、超时、版本号、URL |
| **必须外置** | **因机器而异**，放进公开仓库等于把本机环境写死 | 本机字体路径、SDK / JDK / Flutter 路径、代理端口、绝对路径 |

重点关注：

- 本机字体路径（Windows 字体、本机 Flutter 缓存里的图标字体）→ **必须外置**。
  改法：读环境变量 / 配置，或把路径集中到一个可在本地覆盖的地方；
  找不到字体时降级跳过，而不是让测试崩。
- `tool/` 下的脚本 → 优先用 `$PSScriptRoot` 相对定位（参考 `tool/make_app_icons.ps1`）。
- 版本号 → 单一来源（`pubspec.yaml` 或包信息 API），**不要在多处各写一份**。
- 文档里的构建命令 → 允许保留项目约定的绝对路径，但要标清"这是本机约定，
  换机器要改"。

> **区分"有意约定"与"本机残留"**：项目刻意记录的便携工具链路径是**文档**，
> 是有意为之，不要一刀切；但**同一个路径出现在代码里**就是残留。

## 4. 逐文件报告表格

审核员对范围内每个文件给一行，五列固定：

| 文件 | 必要性 | 本机信息 | 硬编码 | 结论 |
|---|---|---|---|---|
| `<路径>:<行号>` | 必需 / 默认排除 / 留档例外（理由） | 无 / 提示 / 警告 / 阻断 + 具体是什么 | 合理 / 建议提取 / 必须外置 | 保留 / 改后保留 / 排除 / 阻断 |

规则：

- "本机信息"列**不许写"无"了事**——要么确认无，要么写清命中什么。
- 每条"改后保留"和"排除"都要给出**可执行动作**：改成什么、放哪里。
- "排除"要说明是否要从 git 历史里清（已推送的才涉及，见 §8）。

## 5. 报告格式模板

审核员回复 Lead 时按这个骨架（三选一结论写在最前）：

```markdown
## 结论：✅ 可推送 / ⚠️ 有条件通过 / ⛔ 阻止

范围：<分支名 / 文件清单>
脚本：`tool/check_upload_safety.ps1` → BLOCK=<n> WARN=<n> INFO=<n>（退出码 <n>）

### 阻断项（有则必须修完）
1. `<文件>:<行号>` —— 命中什么、为什么是阻断、怎么改

### 条件（有条件通过时列出）
1. `<文件>:<行号>` —— 改法

### 逐文件意见
| 文件 | 必要性 | 本机信息 | 硬编码 | 结论 |

### 已推送内容的遗留问题
- 严重度 / 影响 / 补救成本 / 建议动作

### 需要 Lead 人眼确认
- 图片清单与要看的点
```

结论只有三种，不要写"基本没问题"：

- **✅ 可推送**：`BLOCK=0`，WARN 逐条有结论，人工项已确认。
- **⚠️ 有条件通过**：列出条件；条件全部落地并复核后即可推。
- **⛔ 阻止**：列出阻断项；修完回到第 1 步重审。

## 6. 工具：`tool/check_upload_safety.ps1`

```powershell
# 默认：只扫 tracked 文件（= 一次 push 会上传的东西）
powershell -NoProfile -ExecutionPolicy Bypass -File .\tool\check_upload_safety.ps1

# 推送前推荐：连暂存 + 未跟踪一起扫（这才是"我接下来要 add 的东西"）
powershell -NoProfile -ExecutionPolicy Bypass -File .\tool\check_upload_safety.ps1 -All

# 只看计数与结论，适合塞进流程
powershell -NoProfile -ExecutionPolicy Bypass -File .\tool\check_upload_safety.ps1 -All -SummaryOnly
```

| 开关 | 作用 |
|---|---|
| `-IncludeStaged` | 加上 `git diff --cached` 的文件 |
| `-IncludeUntracked` | 加上未跟踪（且未被 ignore）的文件 |
| `-All` | 上面两个一起开 |
| `-SummaryOnly` | 只打计数 + 结论 |
| `-VerboseInfo` | 打印每一条 INFO（默认按文件折叠） |
| `-EscapeNonAscii` | 输出里的非 ASCII 转 `\uXXXX`（控制台乱码时用） |
| `-AllowPathPrefix <路径>` | 追加"项目约定"前缀（只对 `.md` 生效） |
| `-MaxBinaryKB <n>` | 单个二进制的必要性告警阈值，默认 512 |
| `-RepoRoot <路径>` | 指定仓库根（默认 = 本脚本所在仓库） |

**退出码**：`0` = 无阻断项；`1` = 有阻断项（**不要推**）；`2` = 脚本跑不起来。

**输出格式**：`文件:行号: [规则id] 命中的内容`，按 `BLOCK / WARN / INFO` 分组。
`BLOCK` 与 `WARN` 全量列出；`INFO` 默认按文件折叠，加 `-VerboseInfo` 展开。

**抑制标记**：源文件里某一行含 `upload-safety:ignore` 时跳过该行的内容规则。
**只用于"文档必须展示原始模式"的场合，不得用来掩盖真实值。**

**脚本的已知盲区**（必须人工补）：

- 图片内容（§7）—— 脚本只看路径与体积。
- 语义判断：一段文字是不是真实个人数据、某个绝对路径算不算"有意约定"。
- git **历史**里的东西（§8）—— 脚本只看当前 worktree/index。
- 被 `.gitignore` 正确忽略的本地文件不会出现在 `tracked` 扫描里（这是对的），
  但脚本会额外做一次 "本地存在却没被 ignore" 的守护检查。

## 7. 人工必查：图片

脚本查不到图片里画了什么。每次范围里有 **新增或修改的图片** 时，审核员要：

1. 用 `git ls-files` 列出被 track 的 `*.png` / `*.jpg` / `*.webp`；
2. 打开看，重点找：手机桌面壁纸、状态栏、天气与定位城市、步数、
   桌面第三方 App 列表、通知内容、聊天截图、真实姓名与头像；
3. 在报告里写清每张图的**用途**，以及"已确认无个人信息"或
   "**需要 Lead 人眼确认**"（不确认不算通过）。

程序渲染出来的 golden / 预览图通常是安全的一类（画面是 App 界面 + 夹具数据），
但**仍要抽查**：确认里面不是真实设备截图、不是真实个人记录。

## 8. 已推送内容的遗留问题

已经推上去的内容，**默认按"已永久公开"处理**。分级应对：

| 情况 | 影响 | 补救 |
|---|---|---|
| 真实私钥 / 密钥库 / 口令进过历史 | **最高优先级**。密钥视为已泄露 | 1) **立刻轮换密钥并重新生成**（旧密钥永久废弃，别指望删历史）；2) 从历史清除（`git filter-repo`，或重建仓库）；3) 重新签名发布，且必须**先卸载再安装**（签名冲突）；4) 在 Release / README 说明"请卸载重装" |
| 个人目录路径 / 设备型号 / 内网信息进过历史 | 身份与设备信息可被关联 | 直接改当前文件即可止血；历史清除成本高、收益低，通常**记录风险 + 不再重复**。若信息敏感度高再评估清历史 |
| 真实个人数据进过历史 | 隐私 | 同上一行，并检查是否还有导出文件残留在历史对象里 |
| 生成产物 / 多余图片进过历史 | 仓库体积，无安全影响 | 当前删除即可；历史体积问题不值得 rewrite |

**历史清除的代价**：所有 commit hash 都会变、其他人的 clone 必须重新拉、
已发布 tag 要重建。所以顺序永远是**先轮换密钥，再决定要不要清历史**——
清历史不能替代轮换。

怎么查历史（只读命令）：

```powershell
# 这个路径在历史里出现过吗（含已删除的）
git log --all --oneline --diff-filter=A -- <路径>
# 历史里每一个对象的名字（含目录与已删除文件）
git rev-list --all --objects | Select-String '<关键字>'
# 全历史内容里搜模式（跳过二进制扩展名）
git rev-list --all --objects | ForEach-Object {
  $p = $_ -split ' ',2
  if ($p[1] -notmatch '\.(png|jpg|apk|jar|so|dll|zip)$' -and (git cat-file -t $p[0]) -eq 'blob') {
    $c = git cat-file -p $p[0] | Out-String
    if ($c -match '<模式>') { "$($p[1])  HIT" }
  }
}
```

> 判定"密钥是否进过历史"时，不能只看当前 worktree，也不能只看 `git log -- <路径>`
> （只有被 commit 过才留痕）。要查**全部 ref 的 object 列表**和**blob 内容**。

## 9. 占位符约定

本文档与所有审核报告在描述本机特征时，一律用下表占位符。
真实值**只存在于本机**，任何情况下不要写进仓库里的文件。

| 占位符 | 指代 |
|---|---|
| `<盘符>` | 本机使用的盘符 |
| `<本机用户名>` | Windows / macOS / Linux 的账户名 |
| `<便携工具链根目录>` | 项目约定的免安装工具链根目录（真实值记在 `docs/DEVELOPMENT.md`） |
| `<工程根目录>` | 本仓库在本机的位置 |
| `<adb 序列号>` | 设备序列号 |
| `<厂商机型号>` | 厂商内部型号串 |
| `<机型>` | 对外可见的机型名 |
| `<本机代理端口>` | 本机代理 / 服务的端口 |
| `<内网网段>` | 内网 IP 段 |
| `<真实口令>` / `<真实证书指纹>` | 凭据类 |
| `<私人邮箱>` | 个人邮箱 |
| `<字体文件>` | 本机字体文件名 |

## 10. 快速流程（TL;DR）

```powershell
# 1. 审核员跑脚本（推送前用 -All）
powershell -NoProfile -ExecutionPolicy Bypass -File .\tool\check_upload_safety.ps1 -All
#    退出码 1 => 有阻断项，停。

# 2. 人工：看新增/修改的图片；确认没有真实设备截图与个人记录。

# 3. 出报告（§5 模板），结论三选一。

# 4. Lead 决定并执行。

# 5. 改动落地后复核，再跑一次，确认 BLOCK=0。
powershell -NoProfile -ExecutionPolicy Bypass -File .\tool\check_upload_safety.ps1 -All -SummaryOnly
```
