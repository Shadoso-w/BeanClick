## 1. 布局示意

### 1.1 表单「研磨刻度」一栏

```
 研磨刻度 ⓘ
 ┌───────────────────────┐  ┌───────────────────┐
 │ 1.5              圈   │  │ 15          click │
 └───────────────────────┘  └───────────────────┘
 相对刻度 60 click
```

- 左边框 `flex: 3`、右边框 `flex: 2`（沿用现状比例与 8px 间距）
- 单位写在**框内右侧**（`InputDecoration.suffixText`）：`圈` / `click`
- 标签右侧一个 `(i)` 图标（`Icons.info_outline`，16px，`onSurfaceVariant`），
  点开弹「怎么算的」对话框（见 1.2）
- 提示行只有一行：`相对刻度 60 click`

### 1.2 点 `ⓘ` 弹的「怎么算的」

```
 ┌────────────────────────────────────┐
 │ 研磨刻度怎么算                       │
 │                                    │
 │ 相对刻度 = 圈 × 每圈 click          │
 │           + click − 零点            │
 │                                    │
 │ 这台磨豆机：每圈 30 click · 零点 0   │
 │ 这次填写：1.5 圈 + 15 click          │
 │ 所以：1.5 × 30 + 15 − 0 = 60 click  │
 │                                    │
 │                       [知道了]      │
 └────────────────────────────────────┘
```

对话框里同时给**通用公式**、**这台磨豆机的参数**、**这次的代入结果** ——
比常驻一行提示更好读，也不会在编辑旧记录时满屏公式。

### 1.3 磨豆机缺「每圈几 click」（存量旧数据，D5）

```
 研磨刻度 ⓘ
 ┌───────────────────────┐  ┌───────────────────┐
 │ 2                圈   │  │ 2           click │
 └───────────────────────┘  └───────────────────┘
 ⚠ 这台磨豆机还没填「每圈几 click」，去磨豆机编辑页补上就能换算
```

不给数字（不瞎算）。补完之后这条记录下次打开就有相对刻度了。

### 1.5 「圈」只收正整数，非法值弹提醒（用户第 5 条要求）

**规则**

| 输入 | 结果 |
|---|---|
| 留空 | **合法**，按 0 圈算（磨豆机停在第 1 圈以内时的正常情况） |
| `1`、`2`、`3`… | 合法 |
| `0` | **非法** → 提示「圈只能是正整数（1、2、3…）；不到一圈请留空，把 click 填在右边」 |
| `1.5`、`-2`、`abc` | **非法** → 同上提示 |
| 粘贴进来的非法值 | 同上（输入阶段挡不住粘贴，靠校验兜底） |

**两道防线**

1. **输入阶段**：圈框用整数键盘 + `FilteringTextInputFormatter.digitsOnly`
   （`0` 仍能敲进去，留给下面那道报错），从键盘基本打不出小数与负号
2. **存盘阶段**：校验器拦下 `0` / 小数，红字提示在框下方，保存按钮不落库

```
 研磨刻度 ⓘ
 ┌───────────────────────┐  ┌───────────────────┐
 │ 0                圈   │  │ 15          click │
 └───────────────────────┘  └───────────────────┘
 ⓘ 圈只能是正整数（1、2、3…）；不到一圈请留空，把 click 填在右边
```

**旧记录里的小数怎么处理**（用户选「自动折成 click」）

打开编辑页时把旧的相对读数**折算成整数圈 + click**：

| 旧值 | 每圈 click | 折算后的表单 |
|---|---|---|
| `1.5` 圈 | 30 | `1` 圈 + `15` click（相对刻度 45） |
| `0.5` 圈 | 30 | 留空 + `15` click（0 圈，相对刻度 15） |
| `2` 圈 | 30 | 原样 `2` 圈 |
| `6.5` 刻度（单位是「段 / 刻度」的机器） | 无 | 尽量拆成整数段 + 余下 click；拆不干净就取整并在ⓘ里注明「旧读数已折算」 |

折算**只发生在表单里**，库里的 `grindSetting` 不动 —— 用户不动它就等于没改，
一旦保存就是一份整数的新读数。

> ⚠️ 需要你知道的取舍：「圈」改成只能整数之后，**「段」类刻度的机器**
> （刻度单位是「段」而不是「click」）如果一圈内有多段，就没法用「a 圈 + b 段」
> 那样记了 —— 按你定的「单位一律用 click」，这时应该把刻度换算成 click 记。
> 按 click 定义的磨豆机不受影响（这是本项目约定的口径）。

## 3. 计算规则（定稿版）

```
相对刻度（click） = a 圈 × 每圈 click + b click − 零点 c
```

| 图例 | 含义 | 来源 |
|---|---|---|
| a | 第一框的圈数 | `brew_logs.grindSetting` |
| 每圈 click | 一圈多少 click | **记录快照** `grinderClicksPerRevolutionSnapshot`（老记录按当时的值） |
| b | 第二框的 click | `brew_logs.grindClicks` |
| c | 零点 | **记录快照** `grinderZeroPointSnapshot`（同上） |

结果取整显示；`零点` 没填按 0 算；只填一个框时另一个按 0 算。
单位**恒为 `click`**（D3）。

### 与现状的差异

| 位置 | 现在（0.1.0） | 改后 |
|---|---|---|
| 表单标签 | 「圈」/「研磨刻度」（有圈时） | **「研磨刻度」+ ⓘ** |
| 表单单位 | 只在 hint 里（`例如：1.5` / `click`） | **框内右侧**：`圈` / `click` |
| 圈框校验 | 无（`1.5` 也收） | **只收正整数**，非法值给提示并拦住保存；留空 = 0 圈 |
| 表单提示行 | `绝对刻度 60（零点 0 + 1.5 圈 × 30 + 15 click）` | `相对刻度 60 click`（算式移进 ⓘ） |
| 零点符号 | **加**零点（方向反了） | **减**零点（D1） |
| 缺每圈 click | 退回「研磨刻度」相对展示 | **提示去补填**（D5） |
| 卡片第二行 | `JX-Pro / 22 click + 15 click` + 方法 chip 在第一行 | `JX-Pro · 相对刻度 75 click`（第一行不动） |
| 磨豆机表单 | 每圈 click 可选 | **必填**（D2） |

## 4. 数据层要不要动

**不用加列、不用改 schema。** 三处调整都在「应用层规则」上：

1. `grinders.clicksPerRevolution` **列仍可空**（保持迁移稳定、也让 JSON 导入能容错），
   但**表单必填 + 建议默认 30**。这样不引入一次 schema 升级。
2. `scaleUnit` 字段保留可写（JSON 兼容），但 UI 不再让人选，**统一按 `click` 展示**；
   以后若要彻底收敛，可以再开一次迁移。
3. 相对刻度抽成**一个纯函数**（`Grinder.relativeClicks(...)` 之类），
   表单、卡片、`(i)` 对话框共用一份，避免三处各算一遍算错。
