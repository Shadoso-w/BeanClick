## A2. 日期/时间选择器中文化

**目标**：「烘焙 / 开袋 / 冲煮时间」的日期选择弹窗现在是**英文**（`September 2026`
`OK` `Cancel`），要中文。

**现状原因**：`MaterialApp` 没配 `flutter_localizations`，`showDatePicker` 用默认英文。

**改法**（纯配置，不动业务代码）：

```dart
// pubspec.yaml: flutter_localizations: {sdk: flutter}
MaterialApp(
  locale: const Locale('zh', 'CN'),          // 界面语言锁中文
  supportedLocales: const [Locale('zh', 'CN')],
  localizationsDelegates: GlobalMaterialLocalizations.delegates,
)
```

**布局示意**（弹窗本身）：日期选择器会变成「2026年9月」「日 一 二 三 四 五 六」、
按钮「取消 / 确定」；`showTimePicker` 同样中文（配合 A3）。

**与现状的差异**：全局生效（所有日期/时间弹窗，含扩展属性里的日期字段）。

**受影响测试**：断言弹窗文案的用例（目前没有专门测弹窗文案的，但要检查一遍）。

## B1. 自定义冲煮方法 tag（如拿铁、摩卡）

**语义（你定的 B1-c）**：**「方法」记做法，「辅料」记加了什么。**
所以「拿铁」既可以作为一个方法（用浓缩 + 牛奶做出来的那杯），
也可以拆成「方法 = 意式浓缩」+「辅料 = 牛奶 150ml」——两条路都支持，用户自己选。

**目标**：方法不限于内置那六个，能自己加「拿铁」「摩卡」「燕麦拿铁」等。

**为什么必须动库**：`brew_logs.method` 用**容忍枚举转换器**解析，遇到认不出的名字
回退成 `null` → 最后显示成「手冲」。直接把自定义名字写进去会**丢方法**。

**方案（已定）**：**加一列存原文**，不动现有 `method` 列

| 存储 | 说明 |
|---|---|
| `brew_logs.method` | 保持现状（内置值存枚举 name，如 `pourOver`）——**旧数据和 JSON 导出都不受影响** |
| `brew_logs.methodLabel`（新，可空 TEXT） | 自定义方法的原文；为空表示「用内置方法」 |
| `app_settings['custom_brew_methods']` | 自定义方法库，JSON 字符串数组，有序 |

显示与统计统一走一个取值：`methodLabel ?? method.label`。

> 为什么放 settings 的 JSON 而不是单开一张表：这个方法库只是「一串有序的名字」，
> 不参与 SQL 的 WHERE/ORDER BY/聚合（统计是在内存里按名字分组），
> 按 `docs/添加新属性指南.md` 的判断标准，它不需要一等列。

**布局示意**（方法那一行）

```text
冲煮方法
[✓ 手冲] [摩卡壶] [拿铁] [榛果摩卡] [＋]
                          ↑ 库里已有的自定义方法（浅色区分）
                                    ↑ 点它新建

点「＋」→ 弹输入框
┌──────────────────────────────┐
│ 新的冲煮方法                  │
│ [ 例如：拿铁、摩卡、燕麦拿铁 ] │
│                  [取消] [保存] │
└──────────────────────────────┘

长按自定义 chip → 菜单
┌──────────────────────────────┐
│ 重命名「拿铁」                │
│ 从列表删除「拿铁」            │
│ （已有 3 条记录在用，删除后   │
│   它们仍显示原文）            │
└──────────────────────────────┘

[更多方法 ▾]  ← 展开内置全集（现有行为不变）
```

**尺寸与状态**：chip 行自动换行；自定义 chip 与内置 chip 同款式但底色略浅
（`surfaceContainerHighest` vs `secondaryContainer`）；「＋」是 `ActionChip`。

**与现状的差异**

- `BrewMethod` 枚举仍是「内置预设」，新增 `methodLabel` 这一层
- 表单方法选择器从 `EnumSelector` 换成「预设 + 自定义 + ＋」组件
- 统计的「方法分布」按 `methodLabel ?? method.label` 分组（**自定义也进统计**，B1-b 按建议默认）
- 导出：JSON 冲煮记录多一个 `methodLabel`；CSV 的「方法」列输出同一个取值
- schema v6：一句 `addColumn`（可空列，旧记录自动为空，不用搬数据）

**受影响测试**：方法选择的表单测试、统计的方法分布、导出编码器（CSV 表头与 JSON 往返）。

```text
辅料                                        [＋ 添加]
┌────────────────────────────────────────────────┐
│ 牛奶                    [ 150 ] (ml ▾)     ✕   │
│ 榛果糖浆                [  10 ] (泵 ▾)     ✕   │
│ 冰块                    [     ] (份 ▾)     ✕   │   ← 量可以留空，只记「加了」
└────────────────────────────────────────────────┘

点「＋ 添加」或点名字栏：
┌────────────────────────────────────────────────┐
│ 选择辅料                                        │
│ ── 常用 ──                                      │
│ [牛奶] [燕麦奶] [榛果糖浆] [焦糖酱] [冰块] [水]  │
│ ── 最近用过 ──                                  │
│ [豆奶] [香草糖浆]                               │
│ ── 新建 ──                                      │
│ [ 输入辅料名…                    ]  [添加]      │
└────────────────────────────────────────────────┘
```

**尺寸与状态**

- 一行 = 名字 + 数量（数字）+ 单位下拉 + 删除按钮
- 数量可空（只记「加了什么」）；单位 **`ml / g / 泵 / 份`**（你定的 B3-a）
- 空态：区块内一行灰字「还没有加辅料」+「＋ 添加」，不占大块空间
- 「常用」= 内置 8 个：牛奶、燕麦奶、豆奶、水、冰块、榛果糖浆、焦糖酱、糖
- 「最近用过」= 从本机记录聚合（去重、按最近使用倒序、排除「常用」里已有的）
- 名字直接存文本，**不建名字表**：历史项靠聚合，用户不用维护清单

**数据模型（schema v6）**：新表 `brew_log_addins`

| 列 | 说明 |
|---|---|
| `id` | 自增主键 |
| `brewLogId` | 外键 → brew_logs，**级联删除** |
| `name` | 辅料名（文本快照，历史永远可读） |
| `amount` | 数量，可空 |
| `unit` | 单位枚举 `AddInUnit`：`ml` / `g` / `pump` / `serving`（显示 ml / g / 泵 / 份） |
| `position` | 显示顺序 |

与 `brew_log_beans` 同构（一条记录多行），删记录时一起删；
索引 `idx_brew_log_addins_brew_log_id`。

导出：JSON 冲煮记录里多一段 `addins`；CSV 的冲煮记录表加一列「辅料」，
写成 `牛奶 150ml、榛果糖浆 1泵`（没填数量的只写名字）。

**记录卡片上的显示**（B3-c 按建议默认）：只在**有辅料时**多一行，
最多列两项，其余折叠成 `+2`：

┌──────────────────────────────────────────┐

## C1. 左滑「收藏 / 删除」

**目标**：现在是**右滑**（按钮出现在左侧），你要**左滑**。

**布局示意**

```text
左滑前
┌────────────────────────────────────────────┐
│ 黑猫拼配（拿铁）                    ★★★★☆ │
│ C40 / 22 click                             │
└────────────────────────────────────────────┘

左滑后
┌───────────────────────────────┬──────┬──────┐
│ 黑猫拼配（拿铁）              │ 收藏 │ 删除 │
└───────────────────────────────┴──────┴──────┘
                                   ↑ 删除靠外侧？
```

**尺寸与状态**：一个按钮 78 宽，两个共 156；滑过半吸附全开，反方向滑回关闭；
滑开时点卡片只收起（现有行为不变）。收藏未收藏时图标/文案切换（现有行为不变）。

**与现状的差异**：`SwipeActions` 改成镜像方向（组件保留，加一个 `direction` 参数：
`start` = 右滑出左侧按钮，`end` = 左滑出右侧按钮）。

**受影响测试**：`record_actions_test.dart` 里 4 个用例的 drag 方向（`Offset(220,0)` →
`Offset(-220,0)`）与「卡片被推到哪边」的断言。

**待确认**

- C1-a 只保留左滑（把右滑去掉），还是两个方向都留？
- C1-b 两个按钮的左右顺序：`收藏 | 删除`（删除在最右）还是 `删除 | 收藏`？
  我建议**删除放最外侧**——手指从左往右滑停的位置，误触删除的概率更低；
  但删除在最右时，滑动距离不用拉满就能点到它，反而更容易误触。你定。
