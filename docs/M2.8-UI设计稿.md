## A2. 日期/时间选择器中文化

**目标**：「烘焙 / 开袋 / 冲煮时间」的日期选择弹窗现在是**英文**（`September 2026`
`OK` `Cancel`），要中文。

**现状原因**：`MaterialApp` 没配 `flutter_localizations`，`showDatePicker` 用默认英文。

**改法**（纯配置，不动业务代码）：

```dart
// pubspec.yaml: flutter_localizations: {sdk: flutter}
MaterialApp(
  locale: const Locale('zh', 'CN'),          // 界面语言锁中文
  supportedLocales: const [Locale('zh', 'CN')],
  localizationsDelegates: GlobalMaterialLocalizations.delegates,
)
```

**布局示意**（弹窗本身）：日期选择器会变成「2026年9月」「日 一 二 三 四 五 六」、
按钮「取消 / 确定」；`showTimePicker` 同样中文（配合 A3）。

**与现状的差异**：全局生效（所有日期/时间弹窗，含扩展属性里的日期字段）。

**受影响测试**：断言弹窗文案的用例（目前没有专门测弹窗文案的，但要检查一遍）。

**待确认**

- A2-a 锁死 `zh_CN`（我建议，因为现在整个界面就是中文），还是跟随系统语言？

## A3. 冲煮时间可选到「时分」

**目标**：选完日期还能选具体几点几分。现在只能选日期，时分永远是「当前时刻」。

**布局示意**（「这一杯」区块里的那一行）：

```text
冲煮时间（改前）
┌────────────────────────────────────────┐
│ 📅 2026-09-27                          │   ← 只有日期，时分看不见也改不了
└────────────────────────────────────────┘

冲煮时间（改后）
┌───────────────────────┐ ┌──────────────┐
│ 📅 2026年9月27日       │ │ 🕐 14:30     │   ← 点左边选日期，点右边选时间
```

**尺寸与状态**

- `DateField` **保留**给纯日期字段（烘焙日期、开袋日期、保修到期）——我建议保留

**受影响测试**：`widget_test.dart` 里断言冲煮时间默认值的用例；表单 fill 时新增一个 key

# 这一杯（冲煮记录表单）

## B1. 自定义冲煮方法 tag（如拿铁、摩卡）

**目标**：方法不限于内置那六个，能自己加「拿铁」「摩卡」「燕麦拿铁」等。

**为什么这项必须动库**：`brew_logs.method` 现在用**容忍枚举转换器**解析，
遇到认不出的名字会回退成 `null` → 最终显示成「手冲」。
也就是**直接把自定义名字写进去会丢方法**。

**两个方案**

```text
方案 A（推荐）：方法列改成自由文本 + 预设列表
  brew_logs.method        TEXT   ← 原样存字符串（内置值存 'pourOver' 这种 name，
                                    自定义值存用户输入的原文）
  自定义方法列表           存 app_settings（JSON 数组），或新表 brew_methods
  显示：能匹配内置枚举 → 用中文标签；否则直接用原文

方案 B：方法单独建表 brew_methods（id / name / isBuiltin / sortOrder）
  brew_logs.methodId 外键 → 需要搬迁现有数据、且导出格式要跟着改
  （重，但以后能排序、能统计、能改名）
```

我倾向 **A**：改动小、导出兼容（CSV/JSON 里还是人类可读的方法名）、
不需要外键迁移；代价是「改方法名」不会同步历史记录（用快照语义，和豆名快照一致）。

**布局示意**（方法那一行）：

```text
冲煮方法（改前）
[✓ 手冲] [摩卡壶] [+ 更多方法]

冲煮方法（改后）
[✓ 手冲] [摩卡壶] [拿铁] [榛果摩卡] [＋]      ← 自定义的排在后面，带一个浅色区分
                                  ↑ 点 + 直接输新名字
[更多方法 ▾]  ← 展开内置全集 + 「管理自定义方法」（重命名 / 删除）
```

**尺寸与状态**：chip 行两行以内自动换行；自定义 chip 长按 → 菜单「重命名 / 删除」；
删除时提示「已有 N 条记录在用，删除后它们会显示为原文」。

**与现状的差异**

- `BrewMethod` 枚举降级为「内置预设」，新增一层「方法名 ↔ 显示标签」解析
- 表单方法选择器从 `EnumSelector` 改成「预设 + 自定义」组件
- 统计页的「方法分布」需要把自定义方法一起统计（或明确只统计内置，见 B1-b）
- 导出：JSON 里 `method` 从枚举 name 变成原始字符串（**导入兼容**要处理）

**待确认**

- B1-a 自定义是**全局库**（一次添加，以后都能选）还是每条记录随手写？
  我建议全局库 + 表单里即时新建
- B1-b 自定义方法要不要进统计的「方法分布」？
- B1-c 「拿铁 / 摩卡」严格说是**饮品**而不是冲煮方法——你是想用方法字段表达饮品，
  还是应该走 B3 辅料（牛奶 + 浓缩 = 拿铁）？两者都做的话，规则是：
  「方法」记做法，「辅料」记加了什么

## B3. 辅料（单开一栏）

**目标**：记录额外加的辅料（牛奶、榛果糖浆…）及其基本参数（毫升数等），
支持自定义项与历史辅料选择。

**布局示意**（放在「核心参数」之后、「评价」之前）：

```text
辅料                                        [＋ 添加]
┌────────────────────────────────────────────────┐
│ 牛奶                    [ 150 ] (ml ▾)     ✕   │
│ 榛果糖浆                [  10 ] (泵 ▾)     ✕   │
│ 冰块                    [     ] (份 ▾)     ✕   │   ← 量可以留空，只记「加了」
└────────────────────────────────────────────────┘

点「＋ 添加」或点名字栏：
┌────────────────────────────────────────────────┐
│ 选择辅料                                        │
│ ── 常用 ──                                      │
│ [牛奶] [燕麦奶] [榛果糖浆] [焦糖酱] [冰块] [水]  │
│ ── 最近用过 ──                                  │
│ [豆奶] [香草糖浆]                               │
│ ── 新建 ──                                      │
│ [ 输入辅料名…                    ]  [添加]      │
└────────────────────────────────────────────────┘
```

**尺寸与状态**

- 一行 = 名字 + 数量（数字）+ 单位下拉 + 删除按钮
- 数量可空（只记「加了什么」）；单位：`ml / g / 泵 / 份`（可扩）
- 空态：只在「这一杯」区块里显示一行灰字「还没有加辅料」+「＋ 添加」，不占大块空间
- 「最近用过」= 本机历史记录里用过的名字自动聚合（不需要用户手工维护清单）

**数据模型（schema v6）**：新表 `brew_log_addins`

| 列 | 说明 |
|---|---|
| `id` | 自增主键 |
| `brewLogId` | 外键 → brew_logs，**级联删除** |
| `name` | 辅料名 |
| `amount` | 数量，可空 |
| `unit` | 单位（`ml` / `g` / `pump` / `serving`） |
| `position` | 显示顺序 |

与 `brew_log_beans` 同构（一条记录多行），删记录时一起删。
导出：JSON 加一段 `brewLogAddins`；CSV 冲煮记录表加一列 `辅料`（写成 `牛奶 150ml、糖浆 1泵`）。

**与现状的差异**：表单新增一个区块；记录卡片要不要显示辅料（见 B3-c）；
导出两处格式变化（导出测试要更新）；schema v6 要走一遍快照 + 保活测试流程。

**待确认**

- B3-a 单位用哪几个？（我建议 `ml / g / 泵 / 份`，可扩）
