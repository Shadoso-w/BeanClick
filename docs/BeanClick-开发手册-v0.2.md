## 1. 项目概述

豆刻是一款面向手冲与摩卡壶用户的轻量咖啡参数记录 App。
核心不是做社区，也不是做商城，而是帮助用户快速记录：

- 豆子信息
- 磨豆机与手磨刻度
- 每杯冲煮参数
- 调磨对比
- 库存消耗
- 导出与复盘

设计原则：

1. **本地优先**：无账号也能完整使用。
2. **快速记录**：底部正中加号一键记录，默认复制上次。
3. **参数可深可浅**：新手看核心字段，进阶用户展开专业字段。
4. **无追踪**：不接广告 SDK，不做用户画像。
5. **开源友好**：代码、文档、Issue、Release 按 GitHub 工作流组织。

## 2. 范围与边界

### MVP 做

- 豆库：新增、编辑、搜索、余量管理。
- 磨豆机：新增、编辑、刻度/click/零点。
- 冲煮记录：手冲、摩卡壶。
- 复制上次：快速生成新记录。
- 搜索：按豆子、磨豆机、方法、评分、标签。
- 导出：JSON / CSV。
- 统计：基础趋势、评分、参数对比。
- 设置：单位、主题、默认方法、导出、关于。

### MVP 不做

- 社区、评论、关注。
- 商城、购买链接。
- 蓝牙秤、设备连接。
- AI 推荐、智能识豆。
- 强制登录。
- 广告与用户追踪。

## 3. 目标用户与核心场景

### 用户

- 手冲新手：想知道“上次怎么冲的”。
- 手冲进阶：想对比研磨刻度、水温、时间、评分。
- 摩卡壶用户：想记录粉量、水量、火力、出液。
- 咖啡豆囤积者：想管理余量、烘焙日期、风味变化。

### 核心场景

1. **每日冲煮记录**
   选豆 → 选磨 → 填参数 → 保存 → 评分。

2. **调磨对比**
   同一豆子、同一磨豆机，对比不同刻度下的评分与风味。

3. **豆子库存管理**
   记录剩余克数，冲煮后自动或手动扣减。

4. **复盘与导出**
   按时间、豆子、方法筛选，导出 CSV / JSON。

## 5. 信息架构

底部 dock：**记录 / 豆库** 两栏 + **正中固定的圆形加号**（原设计是 4 tab +
中间悬浮 FAB，M2 期间按用户确认的方案合并）：

1. **记录**
   时间线列表，展示最近冲煮。支持筛选、搜索、复制，以及右滑收藏 / 删除。

2. **豆库**
   分段：咖啡豆 / 磨豆机。支持库存、烘焙日期、风味标签。

3. **统计**
   评分趋势、方法分布、磨豆机使用、豆子消耗、参数对比。
   已并入「记录」页作为第二个页签，不再单独占一栏。

4. **我的**
   设置、导出/导入、同步、开源许可、关于、反馈。
   移到右上角进入，不再占一栏。

5. **正中加号（新加一杯）**
   固定在 dock 中间，不是悬浮按钮（悬浮按钮会盖住列表最后一条）。
   点击进入记录表单，默认复制上次参数；长按可从收藏的参数里挑一条。

## 6. 数据模型

| 实体 | 关键字段 | 关系 |
|---|---|---|
| CoffeeBean | id、名称、产地、庄园、处理法（可多选）、风味、照片、备注；烘焙日期/烘焙度/余量/价格在 BeanBatch 上 | 1 对多 BeanBatch / BrewLog |
| Grinder | id、品牌、型号、刀盘、刻度单位、零点、每圈 click、备注 | 1 对多 BrewLog |
| BrewLog | id、beanId、grinderId、recipeId、方法、研磨刻度、click、粉量、水量、粉水比、水温、时间、注水段、滤杯、评分、风味、备注、照片 | 属于 Bean/Grinder，可选 Recipe |
| Recipe | id、名称、方法、粉量、水量、粉水比、水温、时间、注水段、研磨建议、备注 | 可选关联 BrewLog |
| Settings | key、value | 单例配置 |

### 6.1 统计实现顺序（已定）

1. **评分趋势**：单折线图，X 轴时间、Y 轴评分。最轻，先落地。
2. **参数对比**：同豆 + 同磨豆机下，按刻度排序的对比表（对应「调磨对比」核心场景）。
3. **消耗**：按时间区间的豆子消耗克数与花费估算。

### 6.2 余量与库存扣减（已定）

- **默认行为**：保存冲煮记录时，按该记录的粉量自动扣减对应豆子的余量。
- **可关闭**：设置 → 库存 → 「冲煮后自动扣减余量」开关，关闭后完全手动。
- **手动兜底**：豆子详情页始终支持手动修改余量。
- **边界**：
  - 自动扣减可扣成负数吗？→ 允许扣到 0 后**继续记录负数差值的提示**，但余量字段下限为 0，并在 UI 上提示「余量不足」。
  - 修改已保存记录的粉量 → **按差值补扣**，不重算整条历史。
  - 删除记录 → **自动回补**已扣的余量（M2.9 按测评反馈改的规则：删错了不该让豆子凭空少一截）。
  回补按各支豆子当时的粉量原路退回；豆子已被删除的用量行跳过。

### 6.3 设置项清单（Settings 实体落库内容）

| key | 含义 | 默认值 |
|---|---|---|
| `themeMode` | 浅色 / 深色 / 跟随系统 | `system` |
| `autoDeductStock` | 冲煮后自动扣减余量 | `true` |
| `defaultMethod` | 默认冲煮方法 | `pourOver` |
| `unitWeight` | 重量单位 | `g` |
| `unitTemp` | 温度单位 | `℃` |
| `exportFormat` | 导出默认格式 | `json` |
| `firstLaunchDone` | 是否已完成引导 | `false` |

## 7. 字段规范

### 手磨 / 磨豆机

- 必填：品牌、型号、**每圈 click 数**（M2.10 起；单位统一用 click）。
- 推荐：零点、每 click 位移（µm）。
- 可选：刀盘类型、校准说明。
- 展示：第一行 `型号 / 零点 0`，第二行 `每圈 30 click · 每 click 30 µm · 最近 2026-01-01`。
  没填的项不占位（M2.9：当前刻度不再混进标题）。

### 冲煮记录

核心字段：

- 方法：手冲 / 摩卡壶（**可自定义**：拿铁、摩卡等，见下）
- 豆子（**拼配时可多支**，见下）
- 辅料（**牛奶、糖浆这类额外加的**，见下）
- 磨豆机
- 研磨刻度（**M2.10 定稿**）：两个框 —— 左边填**圈数**（只收正整数，
  不到一圈就留空）、右边填 click，单位都写在框里；
  提示行给**相对刻度**，算式收在标签旁的 ⓘ 里：
  `相对刻度 = 圈 × 每圈 click + click − 零点`
- 粉量
- 水量
- 粉水比
- 水温
- 总时间
- 冲煮时间：**日期与时分分别可选**（M2.8；新建时选完日期、如果还没设过时分，会顺手弹一次时间选择）
- 评分
- 风味标签
- 备注

**研磨度的零点取记录里的快照**（M2.9）：写记录时把当时的零点与每圈 click
一起存下来，之后改刻度或重新校准零点，历史记录仍按当时的零点解释。

**「每圈几 click」是磨豆机的必填项**（M2.10）；单位统一用 click。
存量的旧磨豆机如果没填，记录表单不瞎算，只提示去磨豆机编辑页补上。
旧记录里的小数圈数（0.1.0 允许）在打开编辑页时折算成「整数圈 + click」，
库里的数据不动。

列表展示（M2.9）：卡片第一行是「**所有豆名 + 方法 chip** + 评分星」，
第二行是 **磨豆机 + 一个相对刻度值**（如 `JX-Pro · 相对刻度 75 click`），
不再出现 `22 click + 15 click` 这种两段写法；拼配写成 `黑猫拼配 + 花魁 [拿铁]`。
日期与时间选择器一律中文（界面语言锁 `zh_CN`）。

自定义冲煮方法与辅料（M2.8 第二批）：

- **方法记做法，辅料记加了什么**。所以「拿铁」既能直接当方法，
  也能拆成「方法 = 意式浓缩 + 辅料 = 牛奶 150ml」，两条路都支持
- 自定义方法是**全局库**：在方法那一行点「＋」新建，以后都能选；
  长按自定义 chip 可重命名 / 从列表删除（只改列表，历史记录保留原来的写法）
- 辅料一行一个：名字 + 数量 + 单位（`ml / g / 泵 / 份`）；数量可留空（只记「加了什么」）。
  名字从「常用 / 最近用过 / 新建」里选，「最近用过」由本机记录自动聚合
- 记录卡片上有辅料时多一行，最多两项、其余折叠成 `+N`

拼配（一条记录用多支豆子，M2.5 决策）：

- 豆子一栏可以「加一支」，每支填**占比**；占比合计必须等于 100%
- 「粉量」此时是**总粉量**，各支按占比分摊，分摊后各支粉量之和严格等于总粉量
  （四舍五入的零头归最后一支）
- 余量按**各支各自的粉量**扣；编辑时按各支的差值补扣，去掉一支则那一支回补
- 同一支豆子不能在一条记录里选两次
- 展示：记录卡片上写 `花魁 + 曼特宁`，下面标 `拼配 14 g + 6 g`；
  导出 CSV 里写 `花魁 70% + 曼特宁 30%`

专业字段折叠：

- TDS、萃取率
- 水质 ppm
- 环境温湿度
- 豆温
- 压力
- 分段注水详情
- 摩卡壶火力、出液量、上壶预热

### 咖啡豆

标准字段：

- 名称、产地、庄园、**处理法（可多选，如「水洗 + 厌氧」）**
- 风味标签、照片、备注（烘焙日期/烘焙度/余量/价格在批次上）

## 8. 核心流程

### 快速记录

1. 点击底部 dock 正中的加号。
2. 默认复制上次记录；**长按**加号右侧那个复制按钮可从收藏的参数里挑一条。
3. 选择豆子、磨豆机。
4. 调整刻度、粉量、水量、水温。
5. 保存并评分。
6. 按 §6.2 默认自动扣减豆子余量（可关闭）。

### 收藏一套参数

1. 在「记录」里向右滑动一条记录。
2. 点「收藏」（只存参数，不动余量；旁边是「删除」，删除会**自动回补**已扣的余量）。
3. 「记录」页搜索框下方的「收藏」筛选可以只看收藏过的。
4. 记新的一杯时长按复制按钮，从收藏列表里挑一条照着冲。

### 调磨对比

1. 选择同一豆子 + 同一磨豆机。
2. 查看历史记录列表。
3. 按刻度排序。
4. 对比评分、风味、时间。
5. 标记“最佳参数”。

### 导出

- **交互**：导出时二选一，**JSON 为备份默认项**。
- JSON：完整备份，可用于恢复与迁移。
- CSV：表格分析，交给 Excel / 表格软件。
- 图片：P1 生成分享卡片。

## 9. UI / UX 规范

- 风格：简约、棕黑为主、灰度较低。
- 主色：咖啡棕、深褐、暖黑。
- 背景：浅色模式米白，暗黑模式深棕黑。
- **主题模式**：浅色 / 深色 / 跟随系统，默认跟随系统，设置内可手动覆盖。
- 字体：系统默认，数字可等宽。
- 控件：大按钮、步进器、滑块、标签选择。
- 表单：核心字段优先，专业字段折叠。
- 操作：单手可完成；主操作按钮固定在底部 dock 正中（不用悬浮按钮，避免遮挡列表）。
- 列表项手势：向右滑动露出「收藏 / 删除」，删除需二次确认。
- 空状态：给出“添加第一支豆子 / 第一台磨豆机”的引导。

## 10. 技术方案

- 框架：Flutter
- 数据库：Drift + SQLite
- 架构：本地优先，Repository 模式
- **状态管理：Riverpod**（编译期安全、不依赖 BuildContext、与 Drift 的 Stream 查询配合自然、样板代码少，契合闲时开发节奏）
- 导出：JSON / CSV
- 同步：预留 WebDAV，iCloud 后续
- 平台：先 Android
- 包体目标：<30MB
- 启动目标：<1.5s
- 隐私：无追踪、无广告 SDK、权限最小化

## 14. GitHub 开源工作流

建议仓库结构：

```text
/docs
  DEVELOPMENT.md
  PRIVACY.md
  CHANGELOG.md
/lib
/test
/.github
  ISSUE_TEMPLATE
  PULL_REQUEST_TEMPLATE
  workflows/flutter.yml
README.md
LICENSE
CONTRIBUTING.md
```

工作流：

- `main` 保护，禁止直接推送。
- 功能分支：`feat/xxx`、`fix/xxx`。
- PR 必须通过 `flutter analyze` 和 `flutter test`。
- GitHub Actions：分析、测试、构建 APK。
- Issue 标签：`P0`、`P1`、`bug`、`feature`、`docs`。
- **许可证（已定）：MIT。** 仓库根目录放 `LICENSE`。
- 文档建议：CC BY 4.0（与代码许可证分离，放在 `docs/` 说明中）。
