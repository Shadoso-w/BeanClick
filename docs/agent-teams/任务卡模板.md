# 任务卡模板

> 一张任务卡 = 派给**一个** subagent 的**最小**工作单元。
> 格式定义见 [`AgentTeams-开发手册.md`](AgentTeams-开发手册.md) §6。
>
> **用法**：Lead 复制 §0 的空模板 → 填满九个字段 → 整段粘进派单 prompt。
> 字段没填满就不许派单 —— "你自己看着办"是所有返工的源头。

---

## 0. 空模板（复制这一块）

```markdown
### M<milestone>-T<nn> <一句话标题>

| 字段 | 内容 |
|---|---|
| **级别** | S / M（L 必须先拆，不许直接派） |
| **目标** | 一句话，可判定。不写"优化""完善" |
| **写作用域** | 文件级清单；不跨 `lib/data` 与 `lib/features` |
| **输入** | 要读的文件 / 设计稿 / 既有实现（只给这一张卡需要的） |
| **依赖** | `blocked_by: <卡号或"无">` / `blocks: <卡号或"无">` |

**步骤**（TDD 三段必须在）

1. **RED** —— 写 <测试文件> 里的一条失败测试，描述 <行为>；运行
   `<命令>`，**确认它失败**，把失败信息贴回来。
2. **GREEN** —— 写刚好能过的最小实现：<具体落点>。
3. **REFACTOR** —— 整理命名与重复，保持测试通过。
4. <其余步骤，如迁移 / 表单接入 / 文档同步>
5. 只格式化**本卡 scope 内**的文件。

**完成定义（DoD）**

- [ ] <逐条可勾选，覆盖那"6 个地方"里属于本卡的每一项>
- [ ] 测试先失败后通过（RED 的输出已保留）
- [ ] 受影响既有测试已同步更新（列出是哪几个）
- [ ] 文档同步（若涉及用户可见行为）

**验收命令**

```powershell
<可直接粘贴执行的命令>
# 期望：<明确的期望输出 / 退出码>
```

**禁止事项**

- [ ] 不碰 git（`add` / `commit` / `push` 都归 `lead`）
- [ ] 不改本卡 scope 之外的文件（尤其别人的 hotspot）
- [ ] <本卡特有的红线>

**卡住时**

按 [`AgentTeams-开发手册.md`](AgentTeams-开发手册.md) §8 返回四态之一：
`DONE` / `DONE_WITH_CONCERNS` / `NEEDS_CONTEXT` / `BLOCKED`。
**不许把 `BLOCKED` 报成 `DONE_WITH_CONCERNS`。**
```

> 样例里的文件名以**真实仓库**为准，Lead 派单前照 `glob` 核对一遍再粘。

## 1. 样例 A：S 级，不动 schema（2–5 分钟）

### M5-T01 开放「法压壶」为可选冲煮方法

| 字段 | 内容 |
|---|---|
| **级别** | S |
| **目标** | `BrewMethod.frenchPress` 出现在记录表单的方法选择器里，且不影响已有记录 |
| **写作用域** | `lib/domain/enums.dart`、`test/domain/entities_test.dart` |
| **输入** | [`docs/添加新属性指南.md`](../添加新属性指南.md) §5（加枚举值不用迁移）；`lib/domain/enums.dart` 现有的 `values` / `selectable` 双列表写法 |
| **依赖** | `blocked_by: 无` / `blocks: 无` |

**步骤**

1. **RED** —— 在 `test/domain/entities_test.dart` 里加一条断言：
   `BrewMethod.selectable` 包含 `frenchPress`。运行 `flutter test test/domain/entities_test.dart`，
   **确认失败**。
2. **GREEN** —— 把 `frenchPress` 从预留区移进 `selectable`（列是 `TEXT`，**不需要迁移**）。
3. **REFACTOR** —— 检查注释是否还写着"预留值"，同步改掉。
4. 只格式化和本卡 scope 内的两个文件。

**DoD**

- [ ] `selectable` 含 `frenchPress`，`values` 顺序未变
- [ ] **没有**改用 `textEnum()`（会破坏未知值降级，[指南 §5.1](../添加新属性指南.md)）
- [ ] 记录表单的方法选择器不写死列表，自动跟着 `selectable` 变（若写死了，说明要加一处落点，**停下来报 `NEEDS_CONTEXT`**）
- [ ] 既有记录读取不受影响（未知值仍优雅降级）

**验收命令**

```powershell
flutter test test/domain/entities_test.dart
flutter analyze
# 期望：测试全绿；No issues found!
```

**禁止事项**

- [ ] 不碰 `lib/data/database.dart`（本卡不涉及 schema）
- [ ] 不新增依赖

## 2. 样例 B：M 级，触发迁移门 MG（10–30 分钟）

### M5-T08 给咖啡豆加一等列「烘焙商」并支持筛选

| 字段 | 内容 |
|---|---|
| **级别** | M |
| **目标** | 豆子新增 `roaster` 字段，可在豆库页按烘焙商筛选；老库升级后数据一条不少 |
| **写作用域** | `lib/data/database.dart`、`lib/data/mappers.dart`、`lib/domain/entities.dart`、`lib/features/beans/bean_form_page.dart`、`lib/features/beans/beans_page.dart`、`test/data/design_decisions_test.dart`、`test/drift/**`（由命令生成） |
| **输入** | [`docs/添加新属性指南.md`](../添加新属性指南.md) §2（**六个落点**）；[`docs/DEVELOPMENT.md`](../DEVELOPMENT.md) §7.4（迁移三条硬规矩 + 快照命令）；`test/data/schema_snapshot_test.dart`（两个守门用例） |
| **依赖** | `blocked_by: 无`（但**必须串行**：`lib/data/database.dart` 是热点，同时刻只有一个写者） / `blocks: M5-T09 统计页按烘焙商分组` |

**步骤**

1. **RED** —— 在 `test/data/design_decisions_test.dart` 加一条失败测试：写入并读回 `roaster`；
   再在 `test/data/schema_snapshot_test.dart` 的 `_fixtures` 里为新版本补一份夹具。
   运行 `flutter test test/data/design_decisions_test.dart`，**确认失败**。
2. **GREEN（数据层六个落点，一处不能少）**
   1. `database.dart`：`TextColumn get roaster => text().nullable()();`（要筛选再加 `@TableIndex`）
   2. `database.dart`：`schemaVersion` 递增 + `onUpgrade` 里 `m.addColumn(coffeeBeans, coffeeBeans.roaster)`
      （**逐列迁移**；不许 `alterTable` 重建表 —— `coffee_beans` 被三个表用外键引用着）
   3. `entities.dart`：字段 + `copyWith` + `toJson` / `fromJson` + `==` / `hashCode`（**五处**）
   4. `mappers.dart`：`toEntity` 与 `toCompanion` **两个方向**
   5. 表单与展示两个页面
   6. 测试
3. **生成物**：`dart run build_runner build --delete-conflicting-outputs`
4. **快照**（两条都要跑，**这就是 MG 门**）
   ```powershell
   dart run drift_dev schema dump lib/data/database.dart test/drift/schemas
   dart run drift_dev schema generate test/drift/schemas test/drift/generated
   ```
5. **REFACTOR** —— 同步 [`docs/M1-DATA-MODEL.md`](../M1-DATA-MODEL.md) 与手册 §6 的字段说明。
6. 只格式化本卡 scope 内的文件。

**DoD**

- [ ] 六个落点全部改到（**漏 `mappers.dart` 时 `flutter analyze` 照样过**，必须靠清单）
- [ ] `onUpgrade` 是逐列迁移；搬迁顺序 = 先建表 → 搬数据 → 最后删旧列（本卡只加列，无删列）
- [ ] 新 dump 了一个快照 → **同时补了一份旧库升级夹具**（不补，`schema_snapshot_test` 会点名）
- [ ] 迁移后的测试里断言：豆子 / 批次 / 拼配用量行 / 扩展属性 / 改过的设置项**全部保留**
- [ ] 断言迁移后**余量扣减仍然工作**
- [ ] `git status --short` 干净（生成物无脏 diff）

**验收命令**

```powershell
dart run build_runner build --delete-conflicting-outputs
flutter test test/data/schema_snapshot_test.dart
flutter test test/data/design_decisions_test.dart
flutter analyze
# 期望：全绿；schema_snapshot 的失败信息里不出现 "unexpected entries"
```

**禁止事项**

- [ ] **不手改** `lib/data/database.g.dart`
- [ ] 不用 `alterTable` 重建表
- [ ] 不删表重建、不 `dropColumn` 已有列
- [ ] 不碰 `lib/features/record/**`（那是另一张卡）

## 3. 样例 C：M 级，触发设计稿门 DG（UI）

### M5-T12 统计页「评分趋势」折线图卡片

| 字段 | 内容 |
|---|---|
| **级别** | M（原始需求「统计三件套」是 L，**已拆**；这是其中第一张） |
| **目标** | 统计页出现一张评分趋势折线图卡片；无数据时显示空态而不是空白图 |
| **写作用域** | `lib/features/stats/stats_page.dart`、`test/features/stats_trend_test.dart` |
| **输入** | 已定稿的设计稿 `docs/M5-评分趋势设计稿.md`（含线框图 + `tool/design_preview/` 渲染 PNG）；[`docs/BeanClick-开发手册-v0.2.md`](../BeanClick-开发手册-v0.2.md) §6.1（统计实现顺序：评分趋势 → 参数对比 → 消耗） |
| **依赖** | `blocked_by: 设计稿签字（用户点头）` / `blocks: M5-T13 参数对比` |

**步骤**

1. **前置**：确认设计稿里**没有** `TBD` / "大概" / "以后再补"。有就返回 `NEEDS_CONTEXT`，
   不要自己拍板 —— DG 门的判定人是用户（[`beanclick-ui-design-gate`](skills/beanclick-ui-design-gate/SKILL.md)）。
2. **RED** —— 在 `test/features/stats_trend_test.dart` 写两条失败测试：
   「有 3 条记录时渲染出折线图」「0 条记录时渲染空态引导」。
   用 `test/helpers/widget_harness.dart` 的组合夹具造数据（**批次模型之后不要再手写
   `CoffeeBean(remainingGrams: ...)`**）；收尾用 `await harness.finish(tester)`。
3. **GREEN** —— 只改 `stats_page.dart`：图表模块 + 空态分支。
4. **REFACTOR** —— 把尺寸 / 颜色字面量提成命名常量（[`REVIEW-BEFORE-PUSH.md`](../REVIEW-BEFORE-PUSH.md) §3C）。
5. **观感复核** —— 需要时用 `tool/design_preview/` 再渲一张真实 PNG 给用户看；
   **渲染脚手架不许放进 `test/`**。
6. 只格式化本卡 scope 内的文件。

**DoD**

- [ ] 有数据与空态**两条路径**都有断言
- [ ] 关键控件有 `Key`（照 `brew.dose` / `bean.name` 的既有做法），测试用 `find.byKey` 而不是按文字找
- [ ] 没有新依赖（图表若不引入包，用 `CustomPaint` 手绘；要引依赖**先停下来问**）
- [ ] 深色模式下颜色取自主题，没有硬编码浅色
- [ ] 设计稿里的每一项都在实现里能找到对应

**验收命令**

```powershell

# 期望：全绿；No issues found!
```

**禁止事项**

- [ ] **不经用户签字不写 UI 代码**（这是本项目的硬规则，[`DEVELOPMENT.md`](../DEVELOPMENT.md) §13.1）

## 4. 样例 D：L 级反例 —— 这样拆是不对的

### ❌ M5-T20 实现 WebDAV 同步

| 字段 | 内容 |
|---|---|
| **级别** | **L —— 不许直接派单** |
| **为什么不能派** | 它同时要：① 选一个同步协议与冲突策略（产品决策）② 加同步状态表（**迁移门 MG**）③ 加网络层与凭据存储（新依赖 + 安全审查）④ 加设置页入口（**设计稿门 DG**）⑤ 加后台任务与错误重试 ⑥ 加一整套集成测试。跨了 `lib/data`、`lib/domain`、`lib/features`、`pubspec.yaml` 四层，**违反 §4.4 的"不能跨层"** |
| **一个 subagent 做一个 L 卡会发生什么** | 它会把这个会话读到 74 KB 的表单页 + 31 KB 的 database.dart，判断力在第 30 分钟开始下降；最后交付一个"能跑但冲突策略是它自己拍的"版本 —— 而冲突策略恰恰是**用户该拍板**的事 |

**正确拆法**（每张都是 S/M，且写作用域互不相交）：

| 卡 | 目标 | 级别 | 门 |
|---|---|---|---|
| M5-T20a | 与用户确认同步范围：只推不拉 / 双向 / 冲突时保留哪一份（**只产出决策文档，不写代码**） | S | G0 |
| M5-T20b | 设计同步状态数据模型 + 迁移方案（产出设计评审 docs，不写代码） | S | G1 + MG 设计 |
| M5-T20c | 落地同步状态表与迁移（`guardian` 独占 `database.dart`） | M | **MG** |
| M5-T20d | 抽出 `SyncTransport` 接口 + 一个内存假实现（不引入任何网络依赖） | M | — |
| M5-T20e | 设置页的同步入口与状态展示（**先出设计稿**） | M | **DG** |
| M5-T20f | 接真实 WebDAV 客户端（**先确认依赖与凭据存储方案**） | M | G0 |
| M5-T20g | 端到端集成测试 + 断网 / 冲突 / 重试三类失败路径 | M | — |

> **判据**：拆完之后，每一张卡都能用一句可判定的话描述目标，并且
> **一个 subagent 只看这一张卡就能开工**。做不到就继续拆。
